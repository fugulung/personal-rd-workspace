# /hub｜開源技術研究

## 啟動條件
- `/ana` 判定重大更新，或使用者明確要求技術／開源研究。
- 已有可靠方案且不需重新選型時，直接重用，不做無效搜尋。

## 研究步驟
1. 確認功能目標、平台、限制與驗收條件。
2. 先查 `Shared/Tech/README.md`、相關共用知識與 L1 專案既有方案，避免重複研究。
3. 需要外部資訊時，搜尋官方文件與 GitHub 原始儲存庫；優先評估少量最相關候選。
4. 比較授權條款、維護狀態、相容性、依賴、效能、安全風險、整合成本；無法查證的項目標示「待驗證」，不捏造數據。
5. 建議最簡可行方案、替代方案及小規模驗證方法；涉及重大決策先請使用者確認。

## 輸出（簡短）
- **推薦方案**：選擇理由與來源連結。
- **比較**：最多 3 個候選，列出關鍵取捨。
- **風險與驗證**：必要的 PoC／測試，以及待決策事項。

## 邊界與知識回寫
- 研究階段不擅自安裝依賴、修改正式程式、操作真實資料或執行 Git Commit／Push。
- 研究結論可作參考，但不等於實作已驗證。
- 待實際開發與 QA 驗證通過後，再先比對相似知識，整合或新增到 `Shared/Tech/References/`、`Solutions/`、`Snippets/` 或 L1 專案知識；必要時更新索引。收錄原則（分類分工、查重、驗證標註、不自動擴大）以 `/ana`「結案知識閉環」為準。
